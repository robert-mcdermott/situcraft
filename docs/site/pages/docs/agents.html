--- title: AI agents description: Let an AI agent such as Claude Code look at your SituCraft projects and results through the Model Context Protocol, read-only unless you give it more, in a window you watch. lede: An AI agent such as Claude Code can ask SituCraft about your projects, datasets and results, and show you the tissue, through situcraft mcp, a Model Context Protocol server. It works in a SituCraft window you see, may only read until you give it more, and every change it makes carries its name and can be undone. ---

Setting it up

Give your agent's client the full path to SituCraft and the argument mcp. For Claude Code, for all your projects:

$ claude mcp add situcraft --scope user -- ~/.local/bin/situcraft mcp

For Claude Desktop, under mcpServers in claude_desktop_config.json (Settings, Developer, Edit Config):

{
  "mcpServers": {
    "situcraft": { "command": "/Users/you/.local/bin/situcraft", "args": ["mcp"] }
  }
}

Cursor, Gemini CLI, VS Code and Codex take the same command and arguments; the MCP reference shows each one's file, and how to check the connection without a client.

What an agent may do

By default an agent may only read and show: describe the project, list what was made, read results and their records, write the methods, and show things in the window. You give it more when you start the server:

LeaveWhat it adds
--allow editsChanging the project: regions, saved views and filters, cluster names, curated labels and reviews, decisions, samples and designs, figures
--allow computeRunning jobs: segmentations, clusterings, labels, graphs, spatial analyses, cohort summaries and comparisons, opening examples; stopping or resuming jobs
--allow filesThis computer's files by path: opening bundles, reading tables, references and images, writing exports; downloading an example

Give several at once, --allow edits,compute, or --allow all. In Claude Code, the flags go after mcp: claude mcp add situcraft --scope user -- ~/.local/bin/situcraft mcp --allow edits,compute. The agent's client offers only the tools it may use, and SituCraft refuses a call that needs more leave than you gave, saying which.

Your window, or one of its own

When SituCraft is already running with your library and remote control on, the agent works in its window, where you are working. Otherwise situcraft mcp starts a SituCraft of its own with your library, opens its window when a tool first needs it, and stops it when the agent's session ends; jobs it did not finish can be resumed in the Jobs view.

The History drawer (⌘J) names the agent with each change it made, and Undo takes any of them back.

What to ask

  • "What is open in SituCraft, and is each bundle healthy?"
  • "List the Lung dataset's segmentations and say how each was made."
  • "Show the tissue around the tumor nest region with CD3E and EPCAM."
  • "How many T cells lie within 50 µm of the tumor nest, and which genes stand out inside it?"
  • "Which labels are enriched near each other, and is the answer the same on the refined segmentation?" (with --allow compute)
  • "Write the methods for the whole project, with their references."

An agent can read your library without opening anything: list_projects, describe_project (a project's datasets and every result, with what each was made from) and get_result (a result's record and its numbers as tables: an enrichment's pairs, Moran's I by gene, a comparison's tests). It asks which cells and transcripts meet conditions with query_cells and query_transcripts, and what a region holds with summarize_region: the conditions are a tree of JSON (all, any and not of a cell's QC numbers, genes, labels, clusters, niches, regions and distances from them), checked and evaluated by SituCraft, never a query string or a command. With --allow edits, save_filter keeps the same cells as a filter your analyses can use. Asked with picture, show_tissue, show_map and figure also give it a picture of what they show, so it sees what you see.

The tools are SituCraft's remote-control actions, under the same names; the MCP reference lists them by the leave each needs. SituCraft's results are research findings about a tissue, never a diagnosis, and its instructions to the agent say so.

Privacy and security

  • Everything runs on this computer, and your data never leave it; the only outbound requests are example downloads, which need --allow files.
  • The leave is checked by SituCraft, not left to the agent.
  • While an agent drives a SituCraft that situcraft mcp started, that SituCraft takes no actions from scripts.
